# GlobalSync Bot

GlobalSync Bot is an ultra-fast, stateless Discord translation bot designed exclusively for high-traffic environments. 

Rather than relying on Discord WebSockets—which scales poorly and hogs memory—GlobalSync uses **Stateless HTTP Interactions**, dropping typical server footprint significantly (~20MB RAM) while executing translation requests directly against Google's Gemini models in real time.

## 🚀 Architecture Highlights

- **Language:** Written natively in `Go (Golang)` for maximum concurrency.
- **Message Broker:** Uses **NATS JetStream** instead of RabbitMQ for lightweight, low-latency queues to absorb global api rate limits perfectly.
- **Caching / Webhook Pooling:** Uses **DragonflyDB** (a multi-threaded Redis replacement doing ~4M ops/sec) to pool webhook IDs and dynamically recycle them to stay underneath Discord's 15-webhook-per-channel ceilings.
- **Model Layer:** Integrates the Agent Development Kit powered by `Gemini 2.5 Flash` (Standard) & `Gemini 3.1 Pro` (Enterprise/Accuracy).
- **gRPC Ready:** Bootstrapped via Protobufs to natively extract workers onto separate VM racks dynamically.

## 🛠️ Setup Guide

### 1. Requirements
Ensure your host machine has installed:
- [Docker](https://www.docker.com/) & Docker-Compose (For Dragonfly, NATS, and Prometheus)
- [Go 1.21+](https://go.dev/)

### 2. Environment Variables
To securely bind your API integrations, create a standard `.env` file or export these onto your machine. A template is included in `.env.example`:

```env
DISCORD_PUBLIC_KEY="your-discord-app-public-key"
GEMINI_API_KEY="your-google-ai-studio-key"
BOT_TOKEN="your-discord-bot-token"
PORT="8080" # Change this if the VM already runs another bot on port 8080
```

Copy the template before first launch:

```bash
cp .env.example .env
```

> **Note:** The `DISCORD_PUBLIC_KEY` controls the ED25519 cryptography handshake ensuring malicious bots cannot spoof commands onto your webhook endpoint. If KingBot shares the same VM, choose a different `PORT` than KingBot's listener port.

### 3. Running the Infrastructure

Launch the caching layer and message broker utilizing docker:
```bash
docker-compose up -d
```
This boots:
* **DragonflyDB** on `:6379`
* **NATS Jetstream** on `:4222` and `:8222`
* **Prometheus Telemetry** on `:9090`

### 4. Running the Bot
Once the infrastructure containers are healthy, boot the Go listener:

```bash
go run cmd/globalsync/main.go
```

The system will now securely await incoming HTTP Discord Event Pings via `localhost:8080/interactions`.

*(If testing locally before deploying to an actual server, launch a reverse proxy like `ngrok http 8080` to safely bounce Discord requests down to your localhost).*

## 🌐 Discord Developer Portal Setup

Since this bot relies on stateless interactions rather than a WebSocket gateway stream, the setup process in Discord is slightly different:

1. **Create the Application:** Go to the [Discord Developer Portal](https://discord.com/developers/applications) and create a New Application.
2. **Grab the Public Key:** On the *General Information* page, copy your **PUBLIC KEY**. Paste this into your `.env` file under `DISCORD_PUBLIC_KEY`. This is mandatory for the cryptographic handshake.
3. **Configure the Interactions Endpoint:** 
   - Ensure your GlobalSync Go bot is currently running and publicly accessible via your VM's domain/IP (or through an `ngrok` tunnel if testing locally).
   - Back on the *General Information* page, locate the **Interactions Endpoint URL** field. 
   - Enter your public URL appended with the interactions route: `https://your-domain.com/interactions`
   - *CRITICAL:* When you hit Save, Discord will instantly send a `PING` payload to verify the endpoint is alive. Your Go bot will natively respond with a `PONG` allowing the URL to save.
4. **Permissions:** Under the *OAuth2 -> URL Generator* tab, check `bot` and `applications.commands` to invite the bot to your server.

## 🤖 Automated Deployment Scripts

For maximum stability, the repository includes a `scripts/` directory designed for seamless lifecycle management.

### Local Development & Ngrok Tunneling
Because this bot utilizes HTTP Interactions, Discord needs a public URL to communicate with for local testing.
1. Run the dependency stack and the local Go binary:
```bash
./scripts/run_local.sh
```
2. In a separate terminal, launch the Ngrok tunnel to expose your local port 8080 to the internet:
```bash
./scripts/ngrok_tunnel.sh
```
3. Copy the secure `Forwarding` URL generated by Ngrok and paste it into Discord's **Interactions Endpoint URL** field *appended* with `/interactions` (e.g. `https://1234-abcd.ngrok.app/interactions`).

### VM Auto-Provisioning (One-Click Setup)
If you are deploying to a fresh Ubuntu or Debian VM, ssh into the VM and run the automated provisioning script to install Go, Docker, NATS, Dragonfly, clone the repository, and bind the systemd daemon:

```bash
apt-get update && apt-get install -y curl
curl -O https://raw.githubusercontent.com/ROCKETexecdevs/GlobalSync-Bot/main/scripts/setup_vm.sh
bash setup_vm.sh
```

### VM Graceful Updates
When you push new code to your repository, you don't need to manually stop, compile, and reboot the system. Instead, just run the deploy script from inside `/opt/GlobalSync-Bot`:

```bash
sudo ./scripts/deploy_vm.sh
```

This will:
1. Trap `SIGTERM` to safely shut down the translation pool.
2. Run a `git pull origin main`.
3. Re-compile the optimized Go binaries (`go build`).
4. Restart the `globalsync.service` background daemon instantly.
